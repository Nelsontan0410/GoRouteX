# GoRouteX UI／UX 审查与重设计方案

日期：2026-09-20。阶段：方案及独立预览，尚未批准实施正式 UI。

## 1. 结论

建议保留蓝色产品主调和橙色确认动作，以「路线工作台」组织界面：Dashboard 先显示路线操作和最近记录；规划页以地图及有序站点为核心；账户、升级及解释文字降低视觉优先级。先统一样式与可访问性，再分页面落地，不重写路线、储存或支付系统。

本轮未修改正式应用。新增文件全部在 `docs/ui-review-2026-09-20/`，当前构建脚本不复制此目录。预览不加载 Firebase、Google Maps 或 Stripe，没有网络接口和真实保存动作。地图是几何示意图，不是导航地图；数值、账户及路线均为明确标注的示例。

## 2. 证据与审查范围

- 视口：应用原始窗口、390×844 手机尺寸、1440×900 桌面尺寸。不同页面覆盖程度见下表，不能据此宣称全站全尺寸通过。

## 3. 已确认问题（P1 2 项；P2 6 项；P3 1 项）

### U01 · P1 · 站点复选框缺少可访问名称

- 证据：浏览器对 `#stopsList` 前三个 checkbox 检查，`aria-label=null`、关联 labels 数量为 0；可访问树仅显示 checkbox 0，邻近站点名称不是其标签。
- 影响：读屏用户无法识别正在选哪个站点。
- 建议：每项关联实际站点名称和必要地址摘要；保留现有 input、value、事件及勾选逻辑。验收 WCAG 1.3.1／4.1.2，并检查标签点击只切换一次。

### U02 · P1 · 登录与注册字段标签未绑定

- 证据：`login.html:133–170`，标签未设置 for，也不包裹对应输入；实际登录可访问树的两个输入没有名称。
- 影响：登录这个核心入口对读屏用户不清楚。
- 建议：绑定现有 input ID，调整视觉表单状态；不修改认证接口或密码规则。注册绑定在源码中同样缺失，注册交互未提交验证。

### U03 · P2 · Route Settings 折叠头缺少原生按钮语义

- 证据：`app.html:3465` 为 div；`app.html:9110` 附近绑定 click；浏览器暴露为 container。
- 影响：不能依赖原生 Tab／Enter／Space 操作，也没有明确展开状态。
- 建议：保留 ID 与单一事件入口，改为 button，提供 aria-expanded／aria-controls，验证没有重复事件或默认提交。

### U04 · P2 · 手机规划页顶部操作过高

- 证据：390×844 截图里四个按钮纵向排列，加提示及绕行工具约占首屏上部 330px。
- 影响：可查看与操作的地图空间减少。
- 建议：提示缩为一段；主要按钮紧凑编排，保留 Confirm、Retrieve、Back；Dashboard 可通过导航访问，不能删除能力。地图保留足够触控区域；不要通过缩小点击目标解决。

### U05 · P2 · Dashboard 信息优先级偏向账户

- 证据：实际首屏先显示登录／储存信息、套餐徽章、Upgrade、Plan Details、ProPlan Admin、Logout，再显示大字品牌、路线动作、历史。
- 影响：用户每次开始规划都需越过多组低频操作。
- 建议：账户归入导航区域；标题与 Start route plan 同行，下面直接展示已有统计和历史。不得发明完成率或收入指标。

### U06 · P2 · 移动导航重名

- 证据：浏览器实际显示 Home/Dashboard、Stops/Plan、Route/Routes、GPS/Tracking、Stops/Stops。
- 影响：两个 Stops 难区分选择站点与管理站点，双层近义词增加噪音。
- 建议：用 Home、Plan、Routes、Saved stops 等明确名称；GPS 现有入口仍须保留可达性并保留当前可用性状态，不因布局删掉功能。

### U07 · P2 · 多层样式覆盖增加视觉回归风险

- 证据：`app.html:3213–3218` 加载 modern-theme、app-experience 及三套 mobile 样式；`app.html:4254` 再加载 lorry-safety。modern-theme 中大量 !important，app-experience 仍存在固定颜色和局部覆盖。
- 影响：一个按钮在不同页面和断点受到不同规则控制；长期继续追加覆盖会增加维护成本。
- 建议：先记录最终生效样式，再按页面迁移到统一 token；仅删除确认被替代且无消费者的旧样式，不直接清空旧文件。

### U08 · P2 · 账户页面过度展示内部术语及重复解释

- 证据：账户 DOM 出现 account.view、billing.manage 等权限键；Developer access 在摘要及提示中重复；Feature access 每项重复解释 available when your plan includes…。
- 影响：用户寻找套餐、额度和付款入口需要扫过大量技术文字。
- 建议：默认展示当前套餐、额度、订阅状态和可执行操作；权限细节放入可展开区。保留开发者豁免的准确提示与所有现有权限判断。

### U09 · P3 · 图标、大小写和标题风格不统一

- 证据：新增站点及地图页使用 emoji；最终路线操作全部大写；其他页面使用普通文字；地图全屏标题仍写 Both Routes。
- 影响：不同页面像不同产品，固定标题可能不适合实际组数。
- 建议：统一文字层级和 SVG 图标；动态标题只读取已有路线集合，不修改分组。

## 4. 不在本轮修复的发现

| ID | 证据／问题 | 影响 | 建议与限制 |
|---|---|---|---|

## 6. 建议设计规范（待批准）

| 项目 | 建议 |

| 主色 | 蓝 #2456C4，用于主操作、选中和焦点 |
| 确认色 | 深橙 #B64D0B，仅保留明确确认动作；不用于每个按钮 |
| 背景／表面 | #F5F7FA／白色；用边框分隔，少量必要阴影 |

| 表单 | 标签在上、错误在字段旁；checkbox 与内容同一对齐行，长文换行不覆盖框 |

断点：桌面 ≥1100 使用侧导航＋内容；700–1099 收窄导航与双列；<700 单列、底部导航，路线页先地图后站点。手机避免横向操作栏藏住按钮。缩小占约 3%、展开约 30% 作为视觉目标，不用固定百分比压扁触控目标；展开区可有限滚动，不能遮住 Google 地图署名及控件。

## 7. 逐页方案

### 登录／注册
沿用认证、字段、校验和入口；统一品牌、按钮与标签绑定；默认聚焦表单，保留找回密码和 Google 登录。不得更改试用、密码要求或注册条款。全球定位与现有 Singapore/Malaysia 文案是否调整需单独批准事实文案。

### Dashboard
顶部标题、Start route plan；紧接已有统计，随后最近路线。桌面表格／手机记录块；加载已有路线仍沿用现有确认和恢复逻辑。账户与计划移入导航或账户区，保留所有入口。不要把“保存的路线”叫“已完成配送”。

### 站点选择／方向排序
搜索、可访问复选框和已选计数突出；起终点、驾驶员、日期、方向排序保持折叠设置。桌面可双列已选列表；手机清晰切换或顺序排列。原选择上限、订单顺序和路线排序模式完全不变。

### 手动规划
顶部一句提示＋操作；限制与绕行收起时并排、同一组件风格。每项只用一个 Edit／Done 控件；不新增 avoid 开关。选择 code 即沿用现有开启行为。展开保持已选状态、搜索与全目录。全球路线的 Singapore 区域判断完全不变。

地图约占工作区 2/3，站点列表约 1/3。长地址允许两行并可查看全文；保留多个组、未分配站点、拖动排序和原有交互。绕行坐标作为现有途经点展示，单独标注而不计配送数量。分段颜色及编号互相对应。提醒保留 advisory 表达，禁止重新引入分享封锁。

预览为 1 组 2 配送点的布局示例；正式落地必须验证 2 组以上、长名称、多 detour，不能照预览硬编码。

### 最终路线／地图预览／全屏
统一标题、返回、地图控制区和状态提示。主要导航与分享保持可找到。保留 Google 分段链接及 waypoint 顺序；地图样式仅改外围容器，不修改几何或商标。保留现有统计口径和提醒。

### 历史
搜索与筛选为紧凑工具条；路线日期、驾驶员、站点数量、状态优先；附加信息展开。原始删除和恢复逻辑不改，不将查看误触成删除。必须保留旧记录缺失字段时的占位和当前限制提醒行为。

### 新增站点／CSV
统一字段、必填提示、搜索坐标反馈及最近新增列表。导入入口与权限保持；列映射、文件格式、配额、重复资料规则不变。导入失败和部分成功的展示需有实际状态证据后设计，不虚构已有能力。

### 账户／套餐／付款
当前套餐、额度、订阅状态优先，其次管理入口及方案比较。内部权限键默认折叠为详细资料。后端价格为唯一来源，不硬编码换汇数值。开发者、试用、已取消、宽限、价格不可用、接口失败必须分别保留原行为。付款日期、试用规则、取消反馈、降级及价格逻辑均不在 UI 改造范围。

### GPS／司机页
统一外壳与可用性提示，保留 Coming soon 等真实状态；不能因设计将未上线功能展示为可用。不启用定位、跟踪或新增服务。

每期单独保存基线和改动清单。当前未确认 Git 仓库，实施时使用范围明确的副本回退；回退不能覆盖用户同期修改。设计预览永远不并入生产入口。

## 9. 验收清单

### 视觉与可访问性
- 390×844、768×1024、1440×900、用户实际窗口检查；预览本轮只验证 390 和 1440。
- 200% 缩放、长地址、中文／英文长文案可读；整页无横向溢出。
- 每个输入有名称，复选框与内容一致，键盘能展开／关闭、看见焦点；对话框焦点恢复。
- 主文对比 ≥4.5:1；触控目标合适；不以颜色作为唯一标识。
- loading／empty／error 不误称完成；持续状态不被普通提示覆盖。
- 手机安全区与底部导航不遮住最后一个按钮。

### 功能保持（正式实施后必须验证）
- 相同输入、配置与 API 返回下，路线分组／顺序／里程／ETA 不因 UI 改造变化。
- code 选择、Singapore 自动出现条件、真实冲突 pins 行为完全一致。
- detour 添加、撤销、清除、跨页返回及历史恢复一致；数量不计配送 stops。
- 分享链接包含同样的绕行坐标和分段顺序；限制不新增封锁。
- 保存和确认结果一致；旧记录可读；不会因展开工具重复请求 Google。
